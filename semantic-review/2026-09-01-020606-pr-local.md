# Home member-account entry

The Home services grid adds an account-management tile through an optional callback, without creating a separate navigation path. `App.tsx` supplies that callback only for local `owner` and `admin` sessions; staff sessions receive no callback and therefore no tile. Activation still goes through `openAccounts`, which repeats the staff denial before loading account data and changing route. The tile imports the shared `UsersIcon` named export. Watch for: no blocking permission, routing, or icon-export issue was found. **Verdict**: APPROVED

## High-level view

The UI visibility rule excludes the only non-privileged local role, `staff`; the role union establishes that the eligible roles are exactly `owner` and `admin`. The tile delegates to the existing guarded handler, so the Home addition does not create an alternate route that skips the role check.

## Privileged account entry stays behind the existing guard

`HomeScreen` renders the account tile only when `onOpenAccounts` is defined. The Home call site in `App.tsx` supplies it when `account.role !== 'staff'`; `LocalAccountRole` is limited to `owner`, `admin`, and `staff`, so the tile is available only to owners and admins. Its press action invokes `openAccounts`, whose own `!account || account.role === 'staff'` denial prevents a direct callback invocation from loading accounts or entering the route as staff.

## Shared users glyph is imported and exported correctly

The tile uses `UsersIcon`, imported as a named export from `ServiceIcon.tsx`, where it is exported as a typed SVG component compatible with the services grid icon contract.
