# Home Offline/Online Sync shortcut

The Home banner now exposes the current Offline/Online state as a Sync shortcut, with the route carrying its Home origin so both the in-screen back control and Android hardware Back return to Home. Settings no longer owns a direct Sync row; its owner-only Supabase setup entry remains, and Sync opened from that setup path continues to fall back to Settings. The Settings prop surface no longer accepts a removed Sync callback, so callers cannot supply stale navigation behavior. Watch for: **confirmed** — the focused navigation test suite does not exercise the new `sync` return targets, so a future default-route change could silently break Home or Settings return behavior.

**Verdict**: APPROVED

## High-level view

The manual router uses an explicit `returnTo: 'home'` only for the Home shortcut. Sync otherwise retains the Settings fallback, preserving Settings/Supabase-origin behavior without keeping a redundant Settings Sync row.

The route resolver and the visible Sync header use the same return target, aligning Android hardware Back and the on-screen Back control for either origin.

## Origin-aware Sync return path

`HomeScreen` invokes its new callback from the Offline/Online pill. `App.tsx` constructs `{ name: 'sync', returnTo: 'home' }`; `SyncScreen` uses that value for its header Back control and `getBackRoute` uses it for Android hardware Back. Home-origin Sync therefore returns to Home on either path.

Settings no longer renders or accepts a direct Sync callback. Its remaining Supabase setup entry leads to `supabaseSetup`, whose Sync action creates the default Sync route. The fallback in both `SyncScreen` and `getBackRoute` is Settings, retaining the Settings/Supabase-origin destination.
